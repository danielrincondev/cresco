Parte 4 — Las cinco reglas que no se negocian

Regla 1 — El puntaje se recalcula, nunca se suma (ADR-005)

puntaje = clamp(base + Σ puntos de acciones VIGENTES del período, piso, techo)

puntajePeriodo es una caché reconstruible. La verdad son las acciones. Si en algún punto te encuentras escribiendo puntajeActual = puntajeActual - 1, para: está mal.

La razón no es purismo. Una acción puede anularse o modificarse tras un reclamo, y en ambos casos pasa a valer 0. Si el puntaje fuera un contador, cualquier fallo lo desincronizaría de la bitácora de forma permanente y sin manera de detectarlo.

Usa siempre calcularPuntaje(). Recalcula en tres momentos: al registrar una acción, al anularla o modificarla, y al cerrar el período.

Regla 2 — No hay catálogo de nombres de acción (DP-002)

El docente elige una categoría y escribe el mensaje con sus propias palabras. Esto se decidió con un profesor real. No inventes una lista de acciones predefinidas.

SignoCategoríasRango de puntos
PositivaDesempeño · Convivencia · Responsabilidad · Puntualidad+1 a +2, a criterio del docente
NegativaIndisciplina · Deshonestidad−1 a −3, a criterio del docente
NegativaResponsabilidad (irresponsabilidad)−1 fijo, sin ajuste

Regla 3 — Los valores viven en el código, no en tu archivo

Todo sale de REGLAS en convex/lib/enums.ts (Apéndice C). Si escribes un 60 o un -5 suelto en conducta.ts, ese número queda desactualizado el día que cambie la regla y nadie se entera.

Los límites por tipo de acción salen de la fila de tipoAccion; la base, el piso y el techo del puntaje salen de la fila de institucion. Eso ya lo estás haciendo bien.

Regla 4 — Con Convex no hay RLS: permisos.ts es la única defensa

Con PostgreSQL había dos capas: el código y las políticas RLS de la base. Convex no tiene la segunda. Si olvidas una comprobación, la consulta no falla: devuelve los datos — al revés de como era antes.

Ninguna lectura ni escritura sobre estudiante, matricula, accionRegistrada, reporteEstudiante o puntajePeriodo ocurre sin pasar antes por permisos.ts. Es la regla 3 del proyecto y ahora nada más la respalda.

Regla 5 — Los errores tienen que llegarle a la pantalla

Un ErrorDominio cruza la frontera de Convex como un fallo genérico, y entonces la app solo puede decir «no pudimos completar la solicitud». Por eso nucleo.ts e interaccion.ts envuelven sus handlers. Haz lo mismo. Copia esta función al principio de conducta.ts:

import { ConvexError, v } from "convex/values";
import { ErrorDominio } from "./lib/guardas";
import { ErrorPermiso } from "./lib/permisos";

/** Los errores esperados conservan código y mensaje al llegar al cliente. */
async function conErroresPublicos<T>(operacion: () => Promise<T>): Promise<T> {
  try {
    return await operacion();
  } catch (error) {
    if (error instanceof ErrorDominio || error instanceof ErrorPermiso) {
      throw new ConvexError({ codigo: error.codigo, mensaje: error.message });
    }
    throw error;
  }
}

Y cada función se declara así — fíjate que el async se mueve adentro:

export const registrarAccion = mutation({
  args: { /* ... */ },
  handler: (ctx, args) => conErroresPublicos(async () => {
    // ... tu código de siempre
  }),
});
Y nunca uses throw new Error(...). Usa ErrorDominio(codigo, mensaje), que la app sí puede distinguir de un fallo inesperado. En tu PR #39 hay tres: curso, año lectivo e institución no encontrados. Son un cambio de una línea cada uno.

6.2 anularAccion

El issue #9 la pide junto con registrarAccion. Reglas:

  • Solo sobre acciones negativas. Una positiva no se anula — no hay nada que reparar.
  • Pasa a estado ANULADA y vale 0 puntos en el recálculo.
  • Se recalcula el puntaje. Nunca se le suman de vuelta los puntos.
  • Nada se borra. La acción sigue en la bitácora, marcada.
export const anularAccion = mutation({
  args: {
    accionRegistradaId: v.id("accionRegistrada"),
    motivo: v.string(),
  },
  handler: (ctx, args) => conErroresPublicos(async () => {
    const accion = await ctx.db.get(args.accionRegistradaId);
    if (accion === null) throw new ErrorDominio("NO_ENCONTRADO", "Esa anotacion no existe.");

    const matricula = await ctx.db.get(accion.matriculaId);
    if (matricula === null) throw new ErrorDominio("NO_ENCONTRADO", "La matricula no existe.");

    // El permiso se comprueba contra el estudiante dueno de la accion.
    const { docente } = await exigirAccesoDocenteAEstudiante(ctx, matricula.estudianteId);

    if (accion.signo !== "NEGATIVA") {
      throw new ErrorDominio("VALIDACION", "Solo se pueden anular las anotaciones negativas.");
    }
    if (accion.estado !== "VIGENTE") {
      throw new ErrorDominio("CONFLICTO", "Esa anotacion ya fue anulada o modificada.");

    const ahora = Date.now();
    await ctx.db.patch(accion._id, {
      estado: "ANULADA",
      resueltaPorDocenteId: docente._id,
      resueltaEn: ahora,
      motivoResolucion: args.motivo.trim(),
      actualizadoEn: ahora,
    });

    await recalcularPuntaje(ctx, matricula._id, accion.periodoAcademicoId);
    return accion._id;
  }),
});

/**
 * ADR-005: el puntaje se recalcula desde las acciones VIGENTES, nunca se suma.
 * Respeta `congelado`: si el parcial ya cerro, no se toca.
 */
export async function recalcularPuntaje(
  ctx: MutationCtx,
  matriculaId: Id<"matricula">,
  periodoAcademicoId: Id<"periodoAcademico">,
): Promise<number | null> {
  const fila = await ctx.db.query("puntajePeriodo")
    .withIndex("por_matricula_periodo", (q) =>
      q.eq("matriculaId", matriculaId).eq("periodoAcademicoId", periodoAcademicoId))
    .unique();
  if (fila === null || fila.congelado) return fila?.puntajeActual ?? null;

  const vigentes = await ctx.db.query("accionRegistrada")
    .withIndex("por_matricula_periodo", (q) =>
      q.eq("matriculaId", matriculaId)
       .eq("periodoAcademicoId", periodoAcademicoId)
       .eq("estado", "VIGENTE"))
    .collect();

  const puntos = vigentes.map((a) => a.puntosAplicados);
  const puntajeActual = calcularPuntaje(
    puntos, fila.puntajeBase, REGLAS.PUNTAJE_MINIMO, REGLAS.PUNTAJE_MAXIMO,
  );

  await ctx.db.patch(fila._id, {
    puntosPositivos: puntos.filter((p) => p > 0).reduce((a, b) => a + b, 0),
    puntosNegativos: puntos.filter((p) => p < 0).reduce((a, b) => a + b, 0),
    puntajeActual,
    franjaConductaId: await franjaDe(ctx, puntajeActual),
    recalculadoEn: Date.now(),
  });
  return puntajeActual;
}

async function presentarReporte(ctx: QueryCtx, reporte: Doc<"reporteEstudiante">) {
  const items = await ctx.db.query("reporteEstudianteItem")
    .withIndex("por_reporte", (q) => q.eq("reporteEstudianteId", reporte._id))
    .collect();

  const acciones = [];
  for (const item of items) {
    if (item.tipoItem !== "ACCION" || item.accionRegistradaId === undefined) continue;
    const accion = await ctx.db.get(item.accionRegistradaId);
    if (accion === null) continue;
    const categoria = await ctx.db.get(accion.categoriaAccionId);
    acciones.push({
      id: accion._id,
      categoria: categoria?.nombre ?? "",
      signo: accion.signo,
      puntos: accion.puntosAplicados,
      descripcion: accion.descripcion,
      estado: accion.estado,
    });
  }

  const franja = reporte.franjaConductaId
    ? await ctx.db.get(reporte.franjaConductaId) : null;

  // Los campos del reporte general del curso, si lo hubo.
  const generales = [];
  if (reporte.reporteGeneralId) {
    const valores = await ctx.db.query("reporteGeneralValor")
      .withIndex("por_reporte_campo", (q) =>
        q.eq("reporteGeneralId", reporte.reporteGeneralId!))
      .collect();
    for (const valor of valores) {
      if (!valor.valorTexto) continue;
      const campo = await ctx.db.get(valor.plantillaCampoId);
      if (campo) generales.push({ etiqueta: campo.etiqueta, texto: valor.valorTexto, orden: campo.orden });
    }
    generales.sort((a, b) => a.orden - b.orden);
  }

  return {
    id: reporte._id,
    fecha: reporte.fecha,
    tieneNovedades: reporte.tieneNovedades,
    puntaje: reporte.puntajeAlCierre,
    franja: franja ? { nombre: franja.nombre, frase: franja.fraseRepresentante, color: franja.colorHex ?? null } : null,
    asistencia: reporte.estadoAsistencia ?? null,
    acciones,
    general: generales.map(({ etiqueta, texto }) => ({ etiqueta, texto })),
  };
}

  args: { estudianteId: v.id("estudiante") },
  handler: (ctx, args) => conErroresPublicos(async () => {
    await exigirVinculo(ctx, args.estudianteId);

    const matricula = await ctx.db.query("matricula")
      .withIndex("por_estudiante_estado", (q) =>
        q.eq("estudianteId", args.estudianteId).eq("estado", "CURSANDO"))
      .unique();
    if (matricula === null) throw new ErrorDominio("NO_ENCONTRADO", "El estudiante no tiene matricula vigente.");

    const curso = await ctx.db.get(matricula.cursoId);
    const periodo = curso === null ? null : await periodoEnCursoDeCurso(ctx, curso);
    if (periodo === null) throw new ErrorDominio("PERIODO_NO_VIGENTE", "No hay un parcial en curso.");

    const puntaje = await ctx.db.query("puntajePeriodo")
      .withIndex("por_matricula_periodo", (q) =>
        q.eq("matriculaId", matricula._id).eq("periodoAcademicoId", periodo._id))
      .unique();

    // Toda la bitacora, incluidas anuladas y modificadas: el representante
    // tiene derecho a ver que una anotacion se corrigio, no que desaparecio.
    const acciones = await ctx.db.query("accionRegistrada")
      .withIndex("por_matricula_periodo", (q) =>
        q.eq("matriculaId", matricula._id).eq("periodoAcademicoId", periodo._id))
      .collect();

    const franja = puntaje?.franjaConductaId
      ? await ctx.db.get(puntaje.franjaConductaId) : null;

    return {
      periodo: { nombre: periodo.nombre, fechaInicio: periodo.fechaInicio, fechaFin: periodo.fechaFin },
      puntaje: puntaje?.puntajeActual ?? REGLAS.PUNTAJE_BASE,
      puntosPositivos: puntaje?.puntosPositivos ?? 0,
      puntosNegativos: puntaje?.puntosNegativos ?? 0,
      congelado: puntaje?.congelado ?? false,
      franja: franja ? { nombre: franja.nombre, frase: franja.fraseRepresentante, color: franja.colorHex ?? null } : null,
      bitacora: acciones
        .sort((a, b) => b.fechaOcurrencia.localeCompare(a.fechaOcurrencia))
        .map((a) => ({
          id: a._id, fecha: a.fechaOcurrencia, signo: a.signo,
          puntos: a.estado === "VIGENTE" ? a.puntosAplicados : 0,
          descripcion: a.descripcion, estado: a.estado,
        })),
    };
  }),
});

9.4 Pruebas del día 5

  • Un representante sin vínculo recibe ErrorPermiso en las tres consultas. Es la prueba S-1 de la matriz de permisos — «el Padre A no puede ver la bitácora del Hijo B».
  • Sin reporte de hoy, reporteDeHoy devuelve hay: false y no lanza error.
  • Un representante gratuito ve 2 reportes anteriores; uno premium ve 7.
  • El de hoy no aparece dentro de «anteriores».
  • La bitácora acumulada incluye las anuladas, y sus puntos salen en 0.

10.2 El cron nocturno

Convex tiene cron propio. El archivo ya existe: movil/convex/crons.ts, con el cron de Kenny dentro. Convex exige que todas las tareas vivan en ese único archivo, así que es el segundo sitio del proyecto donde dos personas escriben en el mismo archivo.

La regla para no pisarse: añade tu bloque debajo del último, nunca edites el de otro, y pon el módulo por delante del nombre. Te dejé el comentario en el sitio exacto.

  { hourUTC: 3, minuteUTC: 0 },

10.3 Pruebas del día 6
